### 1. [ST-6] Керування користувачами, ролі (Адмін, Інженер, Клієнт) та права доступу до проектів
* **Пріоритет:** `HIGH`
* **Статус:** `Реалізовано (Готово до тестування)`
* **Опис ролей:**
  - **Адміністратор (`ADMIN`):** повний доступ, видалення/редагування задач, створення нових проектів, створення користувачів та призначення прав доступу до проектів.
  - **Інженер (`ENGINEER`):** доступ тільки до призначених проектів, переміщення карток по дошці (зміна статусів), відповіді в коментарях, завантаження матеріалів/скріншотів/відео. Заборонено видаляти задачі.
  - **Клієнт (`CLIENT`):** створення задач у призначених проектах, додавання опису, прикріплення скріншотів, відео та матеріалів, написання коментарів. Заборонено видаляти задачі та переналаштовувати проекти.
* **Чек-лист підзадач:**
  - [x] Оновити `Role` enum у Prisma (`ADMIN`, `ENGINEER`, `CLIENT`)
  - [x] Реалізувати перевірки прав доступу до проектів та задач на рівні API
  - [x] Створити API керування користувачами (`/api/users`, `/api/users/[userId]`)
  - [x] Створити API вкладень для завантаження скріншотів, відео та файлів (`/api/.../attachments`)
  - [x] Створити сторінку керування користувачами (`/users`) для адміністратора
  - [x] Приховати кнопку видалення задач для не-адміністраторів
  - [x] Додати посилання на "Користувачі" в Navbar для ролі `ADMIN`

### 2. [ST-4] Налаштування поштового сервера (SMTP), авторизації та першого адміна
* **Пріоритет:** `HIGH`
* **Статус:** `Реалізовано (Готово до тестування)`
* **Опис вимог:**
  - Налаштування підключення до поштового сервера знаходяться у файлі конфігурації (`.env` для локального запуску/Docker та `config.yaml` / `/data/options.json` для Home Assistant).
  - Перший користувач системи (Admin) налаштовується через файл конфігурації (`ADMIN_EMAIL`, `ADMIN_NAME`, `ADMIN_PASSWORD`), без хардкоду.
  - Повноцінний екран входу (`/login`) та реєстрації (`/register`) з блокуванням доступу без авторизації (Next.js Middleware Gate).
  - Модуль надсилання пошти (Nodemailer):
    - Реєстрація користувачів та вітальний email.
    - Відновлення та скидання забутого пароля (`/forgot-password`, `/reset-password`) через безпечний токен.
    - Тестовий fallback: якщо SMTP не налаштовано, посилання виводиться прямо на екрані та в консолі сервера.
* **Чек-лист підзадач:**
  - [x] Додати змінні SMTP та першого адміна до файлу конфігурації (`.env.example`, `config.yaml`)
  - [x] Реалізувати сервіс `src/lib/email.ts` на базі Nodemailer із підтримкою SMTP Host, Port, User, Password, SSL/TLS та options.json
  - [x] Оновити модель даних Prisma (`User`: `passwordHash`, `resetToken`, `resetTokenExpires`)
  - [x] Реалізувати захисний Middleware (`src/middleware.ts`) для маршрутів
  - [x] Реалізувати API та інтерфейс входу (`/login`), реєстрації (`/register`) та відновлення пароля (`/forgot-password`, `/reset-password`)
  - [x] Відображення профілю користувача та кнопка виходу ("Вийти") у верхньому меню (Navbar)

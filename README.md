# STsup — Швидкий Self-Hosted Трекер Завдань (Jira / Linear Альтернатива)

**STsup** — сучасний, швидкий та легкий інструмент управління проєктами й задачами для команд підтримки та розробки. Оптимізований для автономної роботи (Self-Hosted), наднизького споживання ресурсів (~100–150 МБ RAM) та інтеграції в локальні інфраструктури (включаючи **Home Assistant**).

---

## 🌟 Ключові можливості

### 1. Професійний інтерфейс у стилі Jira Work Management
- **3-панельний режим перегляду задач:** швидка навігація між проєктом, списком задач та розгорнутою карткою задачі з коментарями, файлами та підзадачами.
- **Велика крос-проєктна Канбан-дошка (`/boards`):** зведення всіх задач з усіх дозволених користувачу проєктів на єдиній дошці з інтерактивним перетягуванням (Drag & Drop) між етапами (*Беклог*, *В роботі*, *Тестування*, *Готово*).
- **Крос-проєктний навігатор задач (`/issues`):**
  - **Всі задачі:** повний реєстр задач у межах дозволених проєктів.
  - **Призначені мені:** задачі, призначені на поточного користувача з усіх доступних проєктів.
  - **Відкриті задачі:** активні задачі, які очікують або знаходяться в роботі (виключаючи статус «Готово»).
  - Швидкий пошук за кодом, назвою або проєктом.
- **Швидке створення задач (`C` або кнопка «+ Створити»):**
  - Типи задач (*Баг*, *Задача*, *Історія*, *Покращення*, *Підтримка*) з фірмовими іконками та кольорами;
  - Пріоритети (*Низький*, *Середній*, *Високий*, *Терміновий ⚡*);
  - Оцінка складності (Story Points);
  - Дедлайни та прикріплення файлів/скріншотів (`Ctrl+V`).

### 2. Безпека та рольове розмежування прав
- **Головний адміністратор (Primary Admin):**
  - Створюється автоматично при першому старті системи (`admin@stsup.local`);
  - Має глобальний доступ до всіх проєктів, користувачів та системних конфігурацій.
- **Адміністратор (Admin):**
  - Повне керування задачами, колонками та учасниками в межах призначених йому проєктів.
- **Інженер (Engineer):**
  - Робота з задачами: взяття в роботу, зміна статусів, виконання чек-листів, додавання коментарів та файлів.
- **Клієнт (Client):**
  - Створення задач (автоматично потрапляють у початковий статус *Беклог* проєкту);
  - Перегляд задач та додавання коментарів;
  - **Жорстке обмеження прав:** клієнт не має права змінювати виконавця або переводити задачу в інші статуси (на Канбан-дошці перетягування для клієнтів заблоковано).

### 3. Реєстрація користувачів та прив'язка за містом
- Обов'язкове поле **«Місто»** при реєстрації нового облікового запису та при створенні користувача адміністратором.
- Відображення міста в таблиці користувачів (`/users`) для швидкої прив'язки клієнтів до відповідних регіональних проєктів.
- **Обов'язкове підтвердження Email:** самостійно зареєстровані користувачі активуються після переходу за посиланням з листа (або прямою активацією адміністратором). Користувачі, створені адміном, активні одразу.

### 4. Поштовий сервіс (SMTP) та автоматичні сповіщення
- Веб-панель налаштування SMTP (`/settings`) із перевіркою з'єднання в 1 клік.
- Автоматичні email-сповіщення при:
  - Зміні статусу задачі;
  - Призначенні або перепризначенні відповідального виконавця;
  - Додаванні нового коментаря (для автора, виконавця та спостерігачів).
- Відновлення забутого пароля за безпечним одноразовим посиланням (`/forgot-password`).

### 5. Корпоративні сервіси (Waffle Menu)
- Меню швидкого перемикання з 9 крапок у верхньому лівому куті:
  - **STsup Tracker** — перехід до робочих проєктів;
  - **Користувачі та права** — матриця доступів та ролей (`/users`);
  - **Налаштування** — конфігурація поштового сервера SMTP (`/settings`).

### 6. Confluence AI & MCP (Model Context Protocol)
- Підтримка підключення Confluence MCP сервера для автоматичного пошуку документації та генерації рекомендацій щодо вирішення інцидентів.

## 🚀 Швидкий запуск через Docker Compose (Рекомендовано)

Найпростіший спосіб запустити повністю автономний сервіс із внутрішньою БД PostgreSQL:

```bash
docker compose up -d --build
```

Після запуску відкрийте браузер:
👉 **[http://localhost:3000](http://localhost:3000)**

- **Логін за замовчуванням:** `admin@stsup.local`
- **Пароль за замовчуванням:** `admin` *(рекомендується змінити після першого входу)*

## 🛠 Локальна розробка (без Docker)

### 1. Встановлення залежностей:
```bash
npm install
```

### 2. Налаштування змінних оточення:
Створіть файл `.env` на основі `.env.example`:
```env
DATABASE_URL="postgresql://stuser:stpassword@localhost:5432/stsup_db?schema=public"
JWT_SECRET="stsup_super_secret_jwt_key_2026"
ADMIN_EMAIL="admin@stsup.local"
ADMIN_PASSWORD="admin"
ADMIN_NAME="Євген"
PORT=3000
```

### 3. Генерація Prisma Client та міграція схеми:
```bash
npx prisma generate
npx prisma db push
```

### 4. Запуск сервера розробки:
```bash
npm run dev
```

## 🏠 Розгортання на Home Assistant

Завдяки ощадливому використанню оперативної пам'яті (~120 МБ) STsup ідеально підходить для розгортання на домашніх серверах та шлюзах Home Assistant:
1. **Через Portainer / Docker:** додайте вміст репозиторію у стек Portainer.
2. **Як локальний Add-on:** скопіюйте репозиторій у каталог `/addons/stsup` та встановіть через меню додатків Home Assistant.
